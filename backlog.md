| T009 | `kicad_symbol_overlap.json`'s mapping is ambiguous for short/generic symbol names (e.g. `"R"`) - `symbol_lib_for()` picked the wrong library and broke a real build | ready | unassigned | Found during T005: the push-button candidate's generic resistor (`"R"`) got mapped to library `"74xx_IEEE"` instead of the correct `"Device"`, causing a real build failure (recovered only by a lucky retry, not a real fix). Root cause: the original grep-based overlap detection (built in T003) matches the literal substring `"R"` anywhere in a `.kicad_sym` file - including inside pin names/properties of unrelated symbols - not specifically as a top-level symbol name, so short generic IDs like `R`/`C`/`L`/`D` resolve to a long, mostly-wrong candidate list, and `symbol_lib_for()` just takes the first one arbitrarily. Likely affects other single/short-letter generic part IDs too, not just `"R"` - not yet checked how many. Suggested fix: rebuild the overlap detection to match symbol names precisely (e.g. parse each `.kicad_sym` file's actual top-level symbol definitions rather than grepping for a substring), or at minimum special-case the small set of generic passive IDs (`R`, `C`, `L`, `D`, `LED`) to their known-correct library (`Device`) directly. Not deferred like T006-T008 - this one is a confirmed, already-observed real build failure, not a hypothetical. |
